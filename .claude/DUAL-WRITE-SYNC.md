## Overview

The **dual-write-sync** hook ensures that every observation saved to Engram is ALSO written to disk (`.pipeline/{cajon}.md`) as a fallback mechanism.

**Purpose**: 
- Resilience when Engram is unavailable (timeout, MCP down, network issue)
- Automatic backup of memory state without manual intervention
- Zero data loss guarantee: if Engram succeeds + disk fails (or vice versa), both are valid sources

---

## How It Works

### 1. Hook Trigger Point

When `mem_save()` succeeds in Engram:
```
Agent calls: mem_save(content="...", topic_key="atlas/...", ...)
     ↓
Engram: observation saved ✅
     ↓
Hook: post-mem-save triggers dual-write-sync.sh
     ↓
Disk: .pipeline/atlas-....md written ✅
```

**Non-blocking**: If disk write fails, Engram is still valid. Hook doesn't block the agent.

### 2. File Path Convention

Topic_key → disk path conversion:

| Topic_key | Disk path |
|-----------|-----------|
| `atlas/boot-state` | `.pipeline/atlas-boot-state.md` |
| `atlas/decision-boot-sequence` | `.pipeline/atlas-decision-boot-sequence.md` |
| `atlas/discovery-dual-write-race` | `.pipeline/atlas-discovery-dual-write-race.md` |

Format: Replace "/" with "-", add `.md` extension, store in `.pipeline/` directory.

### 3. Atomic Writes (No Corruption)

The hook uses temp file + atomic rename pattern:

```bash
# Write to temp file (safe, invisible to readers)
cat > .pipeline/atlas-boot-state.md.tmp.12345 << EOF
content...
EOF

# Atomic rename (either succeeds completely or not at all)
mv .pipeline/atlas-boot-state.md.tmp.12345 .pipeline/atlas-boot-state.md
```

**Safety guarantee**: Even if process crashes mid-write, final file is either:
- ✅ Complete and valid, OR
- ❌ Missing (temp file stays, original untouched)

No partial/corrupted files.

---

## Fallback Behavior

### Scenario 1: Normal Operation

```
Agent → Engram writes ✅ → Disk writes ✅
Result: Both Engram and disk have data (2 copies)
```

### Scenario 2: Engram Timeout (Network issue)

```
Agent → Engram timeout ❌ → Disk writes ✅
Result: Disk has data. On next boot, orquestador tries Engram first (fails), 
        falls back to disk and migrates back to Engram.
```

### Scenario 3: Disk Write Fails (Permission denied)

```
Agent → Engram writes ✅ → Disk writes ❌
Result: Engram is valid. Hook logs warning but doesn't block.
        Dual-write is fallback, not primary — failure is non-critical.
```
